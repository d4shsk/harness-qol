# Harness-QOL

Локальный постоянный плагин для DeepSeek Harness (Host + Web/Desktop Client).

## Возможности

- **Plugins → Harness-QOL → Modules (1.4.0)**: управление модулями на странице плагина, над штатным списком Components. Отдельный раздел Harness QOL в Settings удалён. Названия и короткие описания модулей отображаются на английском при любом языке интерфейса.
  - Возможность индивидуально включать и выключать каждый из 6 модулей:
    1. **Мультипапочные воркспейсы (`workspaces`)** — диалог добавления и редактирования папок, пункт меню «Редактировать workspace…», контекст для агента.
    2. **Модель по умолчанию (`models`)** — выбор модели по умолчанию для новых сессий в Настройки → Default models
    3. **Фоновые вопросы (`btw`)** — команда `/btw` и карточка ответа.
    4. **Цитирование ответов (`quote`)** — контекстное меню «Quote», карточка цитаты над composer и Markdown-цитаты.
    5. **Просмотр и копирование картинок (`images`)** — полноэкранный Lightbox и контекстное меню копирования PNG в буфер.
    6. **Интерактивная консоль процессов (`console`, 1.5.0)** — запуск фоновых процессов с сохранённым stdin и ввод команд во вкладке «Процессы» рядом с Chat/Trajectory.
  - Быстрые действия: «Включить все» и «Выключить все», счётчик активных модулей.
  - Используется штатный slot `plugins.bundle.config` с ключом `@local/harness-qol`, без DOM-наблюдателя, подмены иконок и таймеров. Настройки перечитываются при открытии страницы; формат сохранённых данных не менялся.
  - Изменения применяются мгновенно на клиенте и хосте, настройки сохраняются в `~/.dsh/harness-qol-settings.json`.

- **Workspace с несколькими папками (1.2.0)**: штатная кнопка добавления workspace в боковой панели и на пустом экране чата открывает диалог с названием и списком исходных папок. Компактная строка «Добавить папку» открывает штатный выбор папки; отдельного ручного ввода пути в диалоге нет. Перед сохранением папки можно убрать, полный путь виден при наведении на название.
  - **Редактирование (1.4.1)**: кнопка **Workspaces** внизу боковой панели рядом с Settings открывает список всех workspace, включая пустые. Нажмите на нужный workspace, чтобы переименовать его, добавить или убрать дополнительные папки. После сохранения или отмены возвращается список; ошибки загрузки показываются с кнопкой повтора. В свёрнутой панели остаётся иконка с подсказкой Workspaces. Кнопка отключается вместе с модулем `workspaces`. Также доступен пункт **«Редактировать workspace…»** в меню строки сессии (`...`); штатное меню заголовка workspace не изменяется. Изменения применяются только после сохранения; отмена ничего не пишет. Сам Harness не меняется.
  - Первая папка — неизменяемая основная рабочая директория: это сохраняет идентичность workspace и привязку старых чатов. Остальные папки хранятся в отдельном домене штатного storage профиля и передаются агенту с абсолютными путями в динамическом контексте при следующем запросе. Стандартная панель файлов и относительные пути остаются привязаны к основной директории; это не замена её дерева на multi-root Explorer. Файлы не копируются, не перемещаются, симлинки в проектах не создаются; права доступа не расширяются.
  - Допускается 1–32 папки. Симлинки и повторяющиеся пути канонизируются и объединяются. Изменение устаревшего снимка отклоняется вместо перезаписи чужих правок. Не подключённые сейчас, но ранее сохранённые папки можно оставить или убрать.
  - Инструмент `harness_qol_workspaces` использует те же операции, что UI: `list`, `read`, `create`, `update`. Для обновления передаются полный список папок, название и свежая `revision` из `read`.

- **ПКМ по выделенному тексту ответа агента → «Цитировать» (Quote).** При выделении фрагмента ответа ассистента в чате и вызове контекстного меню (ПКМ или Shift+F10) появляется опция «Цитировать» (и «Копировать»). При выборе цитата визуально отображается в поле ввода промпта в виде карточки цитаты над полем ввода (с акцентной линией, текстом цитаты и кнопкой отмены «×»). При отправке следующего сообщения (нажатие Enter или кнопки отправки) цитата автоматически добавляется в начало промпта в формате Markdown-цитаты (`> ...`), передавая модели контекст.
- **ПКМ по полноэкранному изображению → «Копировать изображение».** Копирует реальные пиксели в полном разрешении как PNG, а не ссылку или миниатюру. Отдельной кнопки копирования нет. Меню доступно также через Shift+F10; ошибки разрешений буфера обмена показываются в просмотрщике. Поддерживаются изображения пользовательских сообщений, ответов, результатов инструментов и Trajectory. Используются авторизованные загрузчики Harness. Черновики в composer и сторонние прямые вызовы исходной image factory не заменяются. GIF копируется как текущий кадр PNG.
- **`/btw вопрос`** — отдельный read-only запрос к модели по ограниченному текстовому снимку текущего чата. Он не вызывает followup/steer/inject/cancel основного агента и не получает инструменты. Вопрос и результат хранятся как обычная команда; в чате отображаются отдельной раскрытой карточкой /btw с постоянным текстом вопроса, статусом ожидания и читаемым ответом (абзацы, списки, жирный текст и код). Ранее отправленные /btw тоже используют эту карточку. Ответ не попадает в рабочий контекст основного агента. Используется последняя модель запроса текущей сессии (до первого запроса — основной default). Максимум один /btw на сессию, четыре на профиль, ожидание до трёх минут.
  - **Защита от потери ответа в reasoning/thinking**: если рассуждающая модель генерирует ответ внутри блока размышлений (`reasoning-delta` или тегов `<think>`), ответ автоматически извлекается и отображается пользователю, а не теряется с ошибкой «пустой ответ». В системную инструкцию также добавлено прямое требование выводить ответ в теле сообщения.
- **Настройки → Модели → «Модель по умолчанию»**: выбор основной модели по умолчанию с уровнем reasoning для всех новых сессий.
  - Сохраняется через канонический сервис `agentDefaultModel` без параллельных хранилищ.
  - **Защита от перезаписи**: переключение модели внутри чата больше не перезаписывает глобальную модель по умолчанию. Смена модели в чате остаётся локальной для сессии.
  - В версии 1.0.1 защита использует `AsyncLocalStorage` вокруг `sessionController.selectModel`: блокируется только автоматическая запись default из этой асинхронной операции. Проверка стека и общий флаг сохранения удалены. Явное сохранение через настройки/инструмент и другие прямые вызовы `agentDefaultModel.saveSelection` сохраняют обычное поведение. При выгрузке плагина исходные методы восстанавливаются.

Существующий раздел **Subagents → Model selection** не меняется: это список разрешённых моделей, не настройка модели по умолчанию. Разрешения на инструменты и модели плагин не расширяет.

## Интерактивная консоль (1.5.0)

Обычные background jobs — не терминалы: API Harness даёт чтение вывода и остановку, но не запись в stdin. Подключить ввод к уже запущенной обычной задаче нельзя. QOL запускает **новый** процесс с открытым stdin и регистрирует его в штатном списке jobs. Это строковая консоль через pipes, а не PTY: полноэкранные программы, Ctrl+C и интерактивное редактирование shell здесь не эмулируются.

Вкладка **Процессы** показывается только при наличии задач в текущей открытой сессии; её видимость обновляется потоком jobs, даже если вкладка ещё не открывалась. Чтобы запустить первый процесс в пустой сессии, попросите агента использовать `harness_qol_console` с `action: start`. Когда задачи есть, новые процессы можно запускать кнопкой **Новый процесс** внутри вкладки.

Консоль оформлена отдельной карточкой: компактное название процесса, индикатор состояния и типа ввода, ограниченный по высоте блок вывода с приглушёнными метаданными и выделением WARN/ERROR, строка команд и нижняя панель действий. Полная команда и идентификатор находятся в раскрываемом блоке, справка — под кнопкой «?». Стили задаются непосредственно компонентам, без зависимости от разрешения встроенных stylesheet-тегов. Клиентское оформление обновляется без выгрузки Host-плагина и остановки серверов.

Пример заполнения формы запуска:

- Программа: `java` (или абсолютный путь к исполняемому файлу).
- Аргументы: `["-Xmx2G", "-jar", "server.jar", "nogui"]`.
- Рабочая папка: папка вашего Minecraft-сервера. JAR и согласие EULA плагин не скачивает и не создаёт.
- После запуска выберите процесс и отправляйте `list`, `say Привет`, `stop` **без начального `/`**. Каждая отправка добавляет ровно один перевод строки. Стрелки вверх/вниз перебирают последние 100 отправленных строк текущего открытого представления; история не сохраняется отдельно.

Вывод обновляется штатным потоком наблюдения jobs, без чтения курсора `job_output`; отображается ограниченный хвост с предупреждением о пропусках. Доступны закрытие stdin и остановка с подтверждением. Для Minecraft безопаснее отправить `stop`, чтобы сервер сохранил мир. Подтверждение записи означает приём данных stdin, а не успешное выполнение сервером. Команды UI сохраняются в обычном журнале команд сессии; не вводите секреты, если не хотите оставлять их в журнале.

Те же операции доступны агенту через `harness_qol_console`: `list`, `start` (`argv`, необязательный `cwd`), `send` (`jobId`, `text`), `read` (`jobId`, `from` → `next`), `eof`, `stop`. Shell-парсинга нет: каждый аргумент задаётся отдельной строкой. Обычные jobs также можно просматривать и останавливать, но ввод для них недоступен. Вызовы UI и инструмента используют одну Host-операцию. Запуск и ввод не ослабляют sandbox; частичное обеспечение политики отклоняется. При изменении политики или рабочей границы сессии ввод в старый процесс блокируется до перезапуска. Windows sandbox может запретить pipes — в таком случае операция завершается ошибкой, без автоматического обхода или повышения прав.

Лимиты: 8 интерактивных процессов на сессию, 32 на профиль, одна строка до 16 KiB UTF-8. Процессы живут до выхода, остановки, уничтожения владельца или перезапуска Harness; выгрузка QOL останавливает его процессы. Отключение модуля запрещает новые запуски/ввод и скрывает вкладку, но не убивает процессы: остановить их можно штатным списком jobs или действием `stop` инструмента. После обновления загруженного Host-модуля может потребоваться перезапуск Harness; затем обновите страницу.

## Установка

Установить каталог пакета через `plugin_manager install_bundle` с абсолютным путём. Управление профилем вручную не требуется. Плагин включён сразу после успешной live-установки; если клиент не обновился, обновите текущую страницу. Для обновления уже загруженного поколения JavaScript Harness может потребовать перезапуск.

## Разработка

- `node build.mjs` — собрать `client.js` из Client-модулей изображений, моделей и /btw.
- `node --test *.test.mjs tests/*.test.mjs` — изолированные проверки контекста /btw, независимой отмены, буфера изображений и сохранения моделей.
- Новые runtime-файлы перечисляются в `package.json`.
